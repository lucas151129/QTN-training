# AI 批改作業平臺

校內小範圍試用的作業收發與 AI 預批系統。**不是商業產品**，是為了回答一個問題：

> 把評分標準先寫清楚、讓 AI 逐點預批、老師只做確認，
> 能不能真的減輕批改負擔，並讓老師看見「全班邊個概念冇掌握」？

**現在狀態：已接上真實模型（deepseek-flash），英文作文可以用「打字」或「拍照」兩條通道提交，手寫會自動轉成文字。**

- 示範科目：小學英文（作文）；程式沒有寫死科目，換 rubric 即可用於科學、數學、中文
- 規模：1 至 3 個班（每班 40 人以下）、同一個 WiFi；一份作業可同時派給多個班
- 電腦需求：Node.js 22.5 以上（本機測試 24.16），**不需要 npm install**

---

## 30 秒跑起來

```
1. 雙擊「程式\start.bat」
2. 瀏覽器開 http://127.0.0.1:8787
3. 老師帳號 teacher / 1234　（登入後請即改密碼）
   示範學生 2025001 / 1234、2025002 / 1234
4. 學生用同一個 WiFi，開視窗顯示的區網網址（例如 http://192.168.1.23:8787）
```

內建一份示範作業（小六英文 `Writing Task 1 · A Descriptive Paragraph`）、
6A 班 12 人名單、一張示範手寫作文相片（`程式/test/sample-essay.png`）。

想從零開始：關掉伺服器，刪除 `程式/data/` 再啟動。

> **API key** 已寫在 `程式/config.json`（不會被提交，見 `.gitignore`）。
> 換 key 或換模型都只改這個檔案，重啟後看啟動畫面是否顯示「真實模型」。

## 六個 AI 功能

| 功能 | 誰用 | 說明 |
|---|---|---|
| 手寫轉寫 | 自動 | 學生交相片後立即轉成文字，保留原本的拼寫錯誤 |
| 逐點預批 | 老師 | 按評分點給分，每點都要寫出依據，給不出就 0 分並標記 |
| 評語草稿 | 老師 | 用分數與依據草擬 80–120 字評語，老師再改 |
| 出題助手 | 老師 | 輸入一個課題，草擬題目與評分點 |
| 班級洞察 | 老師 | 把統計變成「最弱知識點 + 下一堂 12 分鐘怎樣補」 |
| 學生追問 | 學生 | 「為甚麼是這個分數」，只按老師評語回答，不會改分 |
| 新作業提示 | 學生 | 登入彈一次「你有 N 份新作業」，按「知道了」不再彈 |
| 截止提醒 | 學生 | 首頁橙色橫幅：24 小時內截止、已逾期未交 |
| **錯題精煉** | 學生 | 按扣分記錄自動出 3 題針對練習，即時回饋＋示範答案 |

實測數據、提示詞設計與四個踩過的坑，見 [AI 功能與模型實測](方案文件/06_AI功能與模型實測.md)。

## 一份作業怎樣走

```
老師：匯入名單 →（出題助手草擬）→ 逐題寫評分點 → 開放
學生：登入 → 作答（作文可選「打字」或「拍照」）→ 提交
      ↳ 拍照的，系統 2 秒內轉成文字
老師：按「AI 預批」→ 逐題看建議與依據 →（一鍵「幫我寫」評語）→ 改分 → 發還
學生：看逐題得分與評語 → 不明白可按「為甚麼是這個分數」→ 仍有疑問可向老師提問
老師：看統計 →（AI 教學分析）→ 匯出 CSV
```

## 三個設計原則（改程式前請先讀）

1. **AI 只給建議，老師定分。** 資料庫把 `ai_*` 與 `teacher_*` 分開存，
   發還給學生的永遠是老師確認過的分數。
2. **評分點必須結構化。** AI 只能逐點給分，不能自創標準；沒有評分點的作業不應該用 AI 批。
3. **不確定要大聲講。** AI 給不出依據、信心低、看不到圖、轉寫對不上，都會標記「需老師覆核」。

## 驗證

```
cd 程式
node test/e2e.mjs     # 114 項：註冊核對、提交、雙通道、轉寫、AI 端點、權限、統計、匯出、學情、錯題
node test/live.mjs    # 27 項：真實模型（轉寫準確度、評分、練習生成與判斷、成本）
```

最近一次結果：`e2e 114/114`、`live 27/27`。

`live.mjs` 會拿 `test/sample-essay.png` 做真實測試，並檢查：

- 轉寫與原文詞彙重疊 ≥ 95%；
- **保留學生拼寫錯誤**（`droped`、`relax`），沒有偷偷改正；
- 每一點都有依據，且依據引用了學生原文；
- 評分落在合理範圍。

換模型前先跑一次，不要看文件說明，要看你自己的 key 實際行不行。

## 現在最需要你決定的四件事

1. 用哪一班、哪一科、哪個單元（建議：1 班 × 1 科 × 1 單元 × 4 星期）
2. 家長要不要發通告（功課相片＋姓名＋分數都是個人資料）
3. 老師的示範科目要英文還是中文（英文穩定、中文共鳴大）
4. 誰負責每天開機與備份

細節見 `方案文件/03_你可能未考慮周全的地方.md` 最後一節。

## 已知限制

- 沒有 HTTPS（區網明文）；對外使用前必須加
- 一人一份提交，重交即覆蓋（沒有版本歷史）
- 老師不能在相片上畫圈，只能寫文字評語
- 知識點靠老師手打，沒有統一詞表（學情分析會受影響）
- 單機：伺服器關掉學生就交不到
- 手寫轉寫偶爾仍會改正個別錯字 → 涉及拼寫的評分點要以圖片為準
- 沒有家長端；API key 存在 `config.json`（試用可接受，對外要改）
